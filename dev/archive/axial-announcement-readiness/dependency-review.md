# Dependency review for the announcement

Status: **Compatible security updates implemented after Caden's explicit approval. Integration verification is owned by the main announcement pass. No deployment.** Reviewed September 21, 2026 against `/tmp/axial-announcement-audit.json`, the lockfile/installed manifests, source, maintainer advisories and npm registry metadata. The exposure tables below describe the pre-update baseline.

## Implemented result

Only the requested direct dependency versions changed: web SvelteKit **2.61.1 → 2.70.2**, web Vite **8.0.14 → 8.0.16**, and Vitest **4.1.7 → 4.1.11** across web, multiplayer-worker, core and AI. Their manifest minimums now match the patched versions; Vitest's internal packages remain aligned.

Affected transitive entries now resolve within their parents' declared ranges to **devalue 5.9.4**, **PostCSS 8.5.28**, **nanoid 3.3.19**, **brace-expansion 5.0.12** and **postcss-selector-parser 7.1.6**. No permanent overrides, added direct dependencies, adapter/renderer upgrades or Cloudflare toolchain upgrades remain in the change. The lockfile also contains normal transitive updates of the selected Kit/Vite/Vitest packages, including Vite's Rolldown 1.0.3.

Targeted update commands used `--ignore-scripts` to avoid disturbing the concurrent browser run. The final transitive refresh used `pnpm -r update --depth 100 devalue postcss nanoid brace-expansion postcss-selector-parser --ignore-scripts`. Both installation steps and that refresh completed without peer-dependency warnings. The final direct-importer diff was checked to confirm unrelated top-level versions stayed unchanged; `git diff --check` passed. No web rebuild or test suite was run by this dependency lane; the main pass is running the fresh integration gates afterward.

The resulting `/tmp/axial-announcement-audit-after.json` contains **8 remaining records: 3 high, 4 moderate, 1 low**, down from 24. They are exclusively the existing Kit → cookie finding, two Miniflare → sharp findings, and five Miniflare → undici findings. `pnpm audit` therefore still exits 1. The inherited-pin explanations below apply; this is not a zero-vulnerability claim.

## Decision

Prioritize a targeted SvelteKit update before the release build. Its request-header parsing runs in the production Pages Worker even though the game page sets `ssr = false`. The remaining audit entries predominantly concern developer tooling or framework features Axial does not use. They still deserve maintenance, but the report does **not** establish 24 vulnerabilities reachable by public players.

The audit contains 24 package/advisory records (10 high, 12 moderate, 2 low), including the same Vitest advisory attached to both `vitest` and `@vitest/mocker`. Its `devDependencies: 0` summary is not an exposure classification: package manifests explicitly put most affected tools in `devDependencies`. Conversely, SvelteKit is declared there but generates production server code, so excluding dev dependencies is not sufficient triage.

## Approved update scope

The following scope was approved and completed, with current compatible patch releases used for the transitive entries. It does not change the renderer, Svelte major, adapter, deployment design or game code:

1. Raise web `@sveltejs/kit` to at least **2.70.2**, keeping major 2. Resolve its existing `devalue` dependency to **5.9.2 or later in major 5**. Kit's published `^5.8.1` range permits this. Merely updating Kit may retain the old transitive lock entry, so verify the resolved lockfile.
2. Raise web Vite to **8.0.16 or later in major 8** and align Vitest to **4.1.11 or later in major 4** in web, multiplayer-worker, core and AI packages. Let Vitest select its matching internal packages. Installed Cloudflare test-pool peers permit Vitest `^4.1.0`; no test-pool upgrade is required just for this fix.
3. Refresh only the affected compatible transitive entries: PostCSS **8.5.23+**, nanoid **3.3.18+ within major 3**, brace-expansion **5.0.9+**, selector-parser **7.1.3+**. Existing parent ranges permit these. Prefer ordinary lockfile resolution over overrides or adding them as artificial direct application dependencies. Do not run an unrestricted update of the whole workspace.
4. Inspect the resulting audit and dependency paths. Keep the cookie and Cloudflare tooling cases explicitly documented instead of introducing cross-range overrides just to make the count zero.

These are the minimum versions fixing the supplied findings, not a claim that every future advisory is covered. Registry peer metadata for [Kit 2.70.2](https://registry.npmjs.org/@sveltejs%2fkit/2.70.2), [Vite 8.0.16](https://registry.npmjs.org/vite/8.0.16) and [Vitest 4.1.11](https://registry.npmjs.org/vitest/4.1.11) is compatible with the current Svelte 5 / Vite 8 stack and local Node 24.13.0. Installation completed; runtime compatibility remains subject to the main pass's fresh integration results.

### Transitive blockers and why not to use `latest` blindly

- **Kit → cookie:** both Kit 2.70.2 and current 2.70.3 still specify `cookie: ^0.6.0`. A normal update therefore retains the audit entry. A scoped override to 0.7.x crosses the declared range and should be a separately tested choice. With no matching app sink, it is not justified solely by the low-severity count. [Published Kit manifest](https://registry.npmjs.org/@sveltejs%2fkit/2.70.3).
- **Cloudflare tools → Miniflare → sharp/undici:** installed `@cloudflare/vitest-pool-workers` 0.16.17 pins Wrangler 4.102.0 and Miniflare 4.20260617.0. That Miniflare pins sharp 0.34.5 and undici 7.28.0 exactly. Refreshing the lockfile cannot move those dependencies to patched versions.
- **Updating Wrangler alone leaves the test-pool path:** current Wrangler 4.136.1 uses Miniflare 5.20260921.0-alpha with sharp 0.35.4 and undici 7.29.0. However, current test-pool 0.22.0 pins Wrangler 4.124.0 / Miniflare 5.20260815.0-alpha, whose sharp is still 0.35.2. Thus even updating both top-level tools to today's latest does not eliminate every supplied finding. It also introduces an alpha major of the emulator. [Wrangler manifest](https://registry.npmjs.org/wrangler/4.136.1), [test-pool manifest](https://registry.npmjs.org/@cloudflare%2fvitest-pool-workers/0.22.0), [pinned emulator manifest](https://registry.npmjs.org/miniflare/5.20260815.0-alpha).
- **Sharp's fix crosses its 0.x minor:** replacing 0.34.5 with 0.35.4 underneath an exact pin is not a harmless lockfile refresh. Prefer a supported upstream tool combination when available; otherwise review and test a narrowly scoped override separately. Keep local test/emulator services restricted to the intended development environment and do not feed them untrusted images in the meantime.
